# Certmgr — менеджер сертификатов Let's Encrypt

Веб-приложение в одном контейнере для выпуска бесплатных сертификатов Let's Encrypt
по DNS-01 с ручным добавлением TXT-записей. Поддерживает обычный домен и wildcard
(`example.com` + `*.example.com`), хранит файлы сертификатов на диске и создаёт
задание cron для планового продления.

## Как это работает

1. В веб-интерфейсе указываются домен, email и при необходимости wildcard.
2. Приложение создаёт заказ в Let's Encrypt и показывает TXT-записи, которые нужно
   добавить в DNS.
3. Вы добавляете записи у DNS-провайдера и нажимаете «Проверить и выпустить».
4. Приложение проверяет TXT через авторитетные и публичные DNS-серверы, отвечает
   на challenge, забирает сертификат и сохраняет его.
5. После первого успешного выпуска создаётся `/etc/cron.d/certmgr` — ежедневная
   проверка продления (по умолчанию за 30 дней до истечения).

Важное ограничение: при ручном DNS-01 **полностью автоматическое продление
невозможно** — значения TXT меняются при каждом заказе. Cron сам создаёт новый
заказ и публикует новые TXT-значения в интерфейсе, после чего нужно снова добавить
их в DNS и нажать «Проверить и выпустить». Если Let's Encrypt переиспользует уже
подтверждённые авторизации, cron завершит продление автоматически.

## Быстрый старт

```bash
cd /opt/compose/certmgr
cp .env.example .env
# задайте надёжный пароль
nano .env
docker compose up -d --build
```

Откройте `http://<сервер>:8090`. Логин и пароль — из `.env`
(`CERTMGR_USER` / `CERTMGR_PASSWORD`).

Если `CERTMGR_PASSWORD` не задан, приложение сгенерирует пароль и покажет его
в `docker logs certmgr`, а также сохранит в `./data/admin_password`.

## Выпуск сертификата

1. Введите домен, например `example.com`.
2. Отметьте «Добавить wildcard», если нужен `*.example.com`.
3. Укажите email для Let's Encrypt.
4. Нажмите «Создать запрос».
5. Добавьте в DNS все показанные TXT-записи для имени `_acme-challenge.example.com`.

Для домена и wildcard имя записи одинаковое, но значений два — нужны обе записи:

```
_acme-challenge.example.com. 300 IN TXT "значение-1"
_acme-challenge.example.com. 300 IN TXT "значение-2"
```

6. Нажмите «Проверить и выпустить». Если DNS ещё не обновился, дождитесь
   распространения и повторите.

Готовые файлы:

```
./data/certs/<домен>/fullchain.pem   # сертификат + цепочка
./data/certs/<домен>/privkey.pem     # приватный ключ, права 0600
```

Их можно скачать из интерфейса или подключить к другому контейнеру как volume.

## Продление

Cron-задание создаётся после первого успешного выпуска:

```
17 3 * * * root cd /app && DATA_DIR=/data ... python -m app.renew >> /data/logs/renew.log 2>&1
```

Каждый день приложение проверяет срок действия. Когда до истечения остаётся
`RENEW_DAYS` дней, создаётся новый заказ и в интерфейсе появляются новые
TXT-значения (статус «Ждёт TXT»). Добавьте их в DNS и нажмите
«Проверить и выпустить».

Старый сертификат остаётся на месте, пока новый не будет выпущен.

## SMTP и уведомления

Настройки SMTP открываются по кнопке «SMTP» в шапке веб-интерфейса во
всплывающем окне «SMTP и уведомления»: сервер, порт, логин, пароль,
отправитель, SSL, получатель-переопределение и публичный URL интерфейса.
Там же есть кнопка отправки тестового письма.

Письма отправляются:

- при создании заказа — со списком TXT-записей, которые нужно добавить в DNS;
- после успешного выпуска — с датой окончания действия;
- при ошибке выпуска — с текстом ошибки.

Получатель — email, указанный при выпуске сертификата. Если в настройках SMTP
задан «Получатель уведомлений», он имеет приоритет.

Пароль SMTP хранится в `./data/smtp.json` с правами `0600` (или в `.env`) и
**не возвращается в интерфейс** — в форме показывается только признак
«Пароль задан». Для `smtp.mail.ru` используйте порт `465` и SSL.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CERTMGR_USER` | `admin` | Логин веб-интерфейса |
| `CERTMGR_PASSWORD` | генерируется | Пароль веб-интерфейса |
| `CERTMGR_PORT` | `8090` | Порт на хосте |
| `CERTMGR_BIND` | `0.0.0.0` | Адрес прослушивания на хосте |
| `RENEW_DAYS` | `30` | За сколько дней начинать продление |
| `ACME_POLL_SECONDS` | `180` | Таймаут ожидания проверки Let's Encrypt |
| `CERTMGR_CRON_TIME` | `17 3` | Время запуска cron (минуты часы) |
| `ACME_DIRECTORY_PRODUCTION` | Let's Encrypt production | Переопределение ACME URL |
| `ACME_DIRECTORY_STAGING` | Let's Encrypt staging | Переопределение ACME URL |
| `SMTP_ENABLED` | `false` | Включить email-уведомления |
| `SMTP_HOST` | `smtp.mail.ru` | SMTP-сервер |
| `SMTP_PORT` | `465` | Порт SMTP |
| `SMTP_USER` | — | Логин SMTP |
| `SMTP_PASSWORD` | — | Пароль SMTP |
| `SMTP_SENDER` | = `SMTP_USER` | Адрес отправителя |
| `SMTP_USE_SSL` | `true` | Использовать SSL |
| `SMTP_NOTIFY_TO` | — | Получатель-переопределение |
| `SMTP_PUBLIC_URL` | — | Ссылка на интерфейс в письмах |

## Безопасность

- Интерфейс закрыт HTTP Basic Auth. Смените пароль в `.env`.
- По умолчанию порт слушает `0.0.0.0`. Если доступ нужен только локально,
  поставьте `CERTMGR_BIND=127.0.0.1`.
- В интерфейсе доступны приватные ключи, поэтому наружу его лучше публиковать
  только через reverse proxy с HTTPS (например, тот же nginx/Caddy).
- Не открывайте порт в интернет без необходимости.

## API

Все методы, кроме `/health`, требуют Basic Auth.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Проверка живости |
| GET | `/api/state` | Состояние сертификатов и cron |
| POST | `/api/issue` | Создать заказ `{domain,email,include_wildcard,staging}` |
| POST | `/api/certs/{domain}/check` | Проверить TXT в DNS |
| POST | `/api/certs/{domain}/verify` | Проверить DNS и запустить выпуск |
| POST | `/api/certs/{domain}/renew` | Создать новый заказ (продление) |
| DELETE | `/api/certs/{domain}` | Удалить сертификат и файлы |
| GET | `/api/certs/{domain}/download/fullchain` | Скачать `fullchain.pem` |
| GET | `/api/certs/{domain}/download/privkey` | Скачать `privkey.pem` |
| GET | `/api/smtp` | Настройки SMTP (пароль скрыт) |
| PUT | `/api/smtp` | Сохранить настройки SMTP |
| POST | `/api/smtp/test` | Отправить тестовое письмо `{to}` |

## Диагностика

```bash
docker compose logs -f certmgr          # веб-приложение и ACME
docker exec certmgr tail -f /data/logs/renew.log   # cron-продление
docker exec certmgr python -m app.renew            # запустить проверку вручную
```

Типовые проблемы:

- **TXT не видны** — подождите TTL/распространения DNS, проверьте, что запись
  добавлена именно для `_acme-challenge.<домен>`, и нажмите проверку повторно.
- **Ошибка Let's Encrypt** — включите staging для отладки, но помните, что его
  сертификаты не доверяются браузерами. У production есть лимиты на выпуск.
- **Домен не проходит валидацию** — убедитесь, что TXT-запись отдаётся
  авторитетным DNS-сервером зоны, а не только кэшем.
